# 云铸工作流：从百万点云到实体参数

目标：把一份三维扫描点云转化为**带误差证据的几何参数报告**。全程使用 cloudforge_* 工具，不手动解读原始点数据。

## 用户引导（先于一切技术判断）

用户往往不知道工具名、预设、甚至文件路径——他们只会说"帮我看看这个扫描""这房间多高""这零件能不能导出图纸"。规则：

1. **没给路径**：先 `ls` 当前工作区找点云文件；没有则探查常见数据目录（如工作区旁的 `data/` 及其子目录），把找到的 .ply/.pcd/.bin 列成简表让用户挑选。文件超过 5 个时只报文件名不逐个侦察，等用户选定后再走标准流程。**找不到文件不要猜路径**，列出你找过的位置并请用户确认。
2. **没说场景**：按下方场景表触发词推断；推断不了不要反复追问，直接按"词义不明"规则双预设对比择优，报告开头用一句话说明选择理由。
3. **报告语言跟随用户水平**：结论先行、证据随后；给非专业用户时写"平整度约 2 mm（robust_sigma 0.002 m）"，不要只堆指标名。
4. **主动给下一步**：报告末尾给 1–2 个用户可能想要的后续（"要导出 CAD/STEP 模型吗""要不要对照设计值核验偏差"），让对话可以延续。

## 场景模式（先判场景，再定报告口吻）

按用户用词判定场景，影响预设选择与报告模板：

| 场景 | 触发词 | 预设 | 报告模板 |
|---|---|---|---|
| **竣工核验**（默认室内） | 验收、竣工、核验、净高、开间、房间、室内 | outdoor | 验收清单（§A） |
| **船舶/机械分段** | 船、分段、法兰、零件、管、孔轴 | mechanical | 精度检测单（§B） |
| **文物构件** | 文物、古建、构件、柱、梁、数字化档案 | mechanical | 构件参数卡（§C） |
| 词义不明 | — | 机械感（含曲面/孔轴）选 mechanical，纯建筑感选 outdoor；**仍不明时两个 preset 各跑一遍，对比内点率与形状质量后择优并向用户说明选择理由** | 通用报告 |

## 标准流程（四阶段闭环）

### 阶段 1：侦察（cloudforge_cloud_info）
对用户给定的点云文件调用 `cloudforge_cloud_info`，拿到：
- `points`（点数）、`span`（包围盒最大边长，单位推断依据）
- `format`、`centered`（TXT/STL 加载后质心居中——报告参数基于该坐标系，需向用户注明）
- 若返回 `ok:false`：向用户说明文件问题（格式不支持/损坏），停止，不要重试其他文件。

### 阶段 2：检测（cloudforge_detect）
按场景选择 preset：
- 建筑/室内/城市扫描（墙、地板、家具为主）→ `preset: "outdoor"`（仅平面、过滤更严）
- 机械零件/工业件（含孔、轴、曲面）→ `preset: "mechanical"`（五类基元全开）
- 无法判断时默认 `mechanical`。

调用后检查返回的每个形状：
- `rmse`（均方根误差）、`robust_sigma`（噪声尺度）、`soft_score`（软内点率，越接近 1 越好）
- `inlier_count / points`（内点占比）

### 阶段 3：反馈与重试（条件分支）
- 若 `shape_count === 0`：点数太少（<100）或预设不匹配 → 换 preset 重试一次；仍为 0 则如实告知。
- 若某形状 `soft_score < 0.6` 或 `inlier_count` 相对 `points` 过小：用 `cloudforge_refine` 对该形状的内点
  （`output_dir` 下 `indices/shape_<id>.txt`）做精拟合，`hint` 传该形状类型。
- `cloudforge_refine` 返回 `ok:false` 且提示 selected<50：说明该形状内点过少，放弃它并在报告中注明，不要重试。

### 阶段 4：验证与报告
- 若用户提供了基准/真值（或这是合成验证任务）：用 `cloudforge_synth` 生成基准、`cloudforge_detect` 检测后
  用 `cloudforge_verify` 判定。`pass:false` 时报告误差数值，不要粉饰。
- 最终输出报告，必须包含：
  1. 输入概况（文件、点数、坐标系说明，centered=true 时注明质心居中）
  2. 检测到的基元清单：类型 + 几何参数（平面方程 nx·x+ny·y+nz·z+d=0；圆柱轴点/轴向/半径；球心/半径）+ 误差三指标
  3. 结论：结构推断（如"检测到地板与两面正交墙体，房间净高约 X m"）
  4. 证据：引用每次工具调用的关键数值，供人工复核

### 阶段 5：CAD 交付（可选，机械/零件类场景默认做）
当用户需要"模型/图纸/CAD/三维文件"时，**先按检测结果选路**：

- **检出形状全部/几乎全部为 Plane（室内/建筑/outdoor 预设）→ 必须走路 A**（建筑剖面骨架），即使用户只说"CAD/模型/导出"也要走路 A；
- **检出含 Cylinder/Sphere/Cone/Torus（机械/零件/mechanical 预设）→ 走路 B**。

**路 A（建筑剖面骨架）**：
用 shell 调建筑剖面骨架工具（自动识别地板/顶棚，每面竖墙按水平投影凸包从地面全高拉伸到顶棚）：
```
python hackathon/tools/room-skeleton.py <detect的result.json绝对路径> <输出.step绝对路径> 800
```
- 点云路径不用传——result.json 的 source_cloud 字段记录了 detect 时的源点云，工具自动读取；
- 产出后照常用 freecad-verify 自检 bbox，报告注明"建筑剖面式骨架：全高隔墙 + 地板 + 顶棚"；
- 若输出为空（无竖直墙检出），退回路 B 并如实说明。

**路 B（机械/零件基元模型）**：
调用 `cloudforge_cad_export`：
- `cloud` 必须与 detect 用的同一文件；`result_dir` 传 detect 的输出目录；`output_py` 指定脚本输出路径；
- `union: true` 生成整体零件（推荐）；`min_inlier` 默认 200，滤掉碎块面片；
- **面数多（30+）时先用 `ids` 精简**：挑主结构面（墙/地/顶或零件主体，按内点数排序），union 大量板片既慢又把包围盒撑大；
- `hull: true`（默认开启）按每面内点的凸包轮廓裁切板片——贴合实际边界、不相互穿透；只有需要与旧版矩形板对比时才关；
- **禁止手写 slab/几何脚本**。已知两个必踩的坑：① `xDir=(nx,0,-nz)` 对法向 ±y 的平面是零向量（墙会变细条）；② box 中心放在 -d·n（平面上离原点最近的点）会让切向位置全错。所有几何裁切由工具完成；
- 生成的是可执行 CadQuery 脚本（`pip install cadquery` 后 `python <output_py>` 导出 STEP）；
- **导出后必须自检**：用 FreeCAD 命令行跑 `hackathon/tools/freecad-verify.py <step文件>`，把 bbox 与点云 span 对比——超出 1.5 倍必须排查（通常是冗余面或 min_inlier 太松），不许直接交付；
- 报告里注明：导出实体的尺寸来自内点范围，坐标系与点云一致（centered=true 时为质心居中系）；
- 若 detect 结果里没有任何可导出形状（全部 <min_inlier），如实说明并建议降低 min_inlier 重试。

**交付预览（自动，两条路共用）**：STEP 验证通过后，自主打开 FreeCAD 展示给用户，不要等用户要求。分三步，**顺序不可省**：

1. 定位（FreeCAD 安装位置不固定）：
```
python hackathon/tools/find-freecad.py
```
返回 JSON：`freecad_exe`（GUI 主程序）、`freecadcmd_exe`（命令行验证也用它）。

2. 启动 + 存活验证（**必须用这个工具，不要用 cmd start**——普通 start 启动的 GUI 会被 shell 的进程树清理误杀，且 start 返回 0 不代表真的打开了）：
```
python hackathon/tools/preview-freecad.py <freecad_exe> <step文件的绝对路径>
```
返回 JSON 含 `alive` 字段。

3. 如实报告：
- `alive: true` → 报告"已在 FreeCAD 中打开 <文件名>（PID xxx），切换到该窗口即可查看"；
- `alive: false` → **必须如实告知**"自动启动失败，请手动打开 <step路径>"，并附 find-freecad 输出的程序位置；严禁在未确认进程存活时声称已打开。

**点云的自动预览（CloudForge GUI）**：用户要看点云本身、或任务以点云文件收尾时，用 CloudForge 桌面版打开（命令行参数会自动加载该点云）：
```
python hackathon/tools/launch-cloudforge.py <点云绝对路径>
```
- 返回 JSON 含 `alive`；`alive: true` → 报告"已在 CloudForge 中打开 <文件名>（PID xxx）"；`alive: false` → 如实告知手动打开；
- 文件类型分派：**STEP → FreeCAD；点云（pcd/ply/txt/bin）→ CloudForge GUI**；两者都要时先启动 CloudForge（点云复核）再启动 FreeCAD（实体复核）。

## 报告参数换算约定
- 系数单位 = 点云坐标单位（室内扫描通常为米）
- 平面：coefficients = [nx, ny, nz, d]，法向已归一化，d 为原点到平面有符号距离
- 圆柱：[px,py,pz, ax,ay,az, r]（轴点、单位轴向、半径）
- 锥：[apexX,apexY,apexZ, ax,ay,az, halfAngle(rad)]（顶点在前！）
- 环：[minorR, majorR, cx,cy,cz, nx,ny,nz]（管半径在主半径之前！）
- 近圆柱可能被检出为半角极小的圆锥（锥是圆柱的几何泛化），报告时换算等效半径并注明

## 三份行业报告模板（按场景模式选用，均须附误差证据）

### §A 竣工核验清单（outdoor）
```
三维数字化竣工核验清单（草稿）
项目/部位：____  点云：____（N 点，采集坐标系，centered=是/否）
【净高】地板(z≈__) 至 顶棚(z≈__)：____ m（两平面 d 差，依据 shape i/j）
【墙体】共 __ 面主墙：法向/倾角/位置（各平面方程 + 平整度 RMSE __mm）
【开间】相邻平行墙面间距：__ m（平面 d 差）
【平整度】以 robust_sigma 报告各面噪声尺度（__mm），超 5mm 的面列为"建议复测"
【结论】与设计值偏差在 ±__mm 内的项 __/____；超差项逐条列出（如实，不粉饰）
【证据】每条参数附 shape id、inlier_count、rmse/robust_sigma、soft_score
```
净高/开间计算规则：取相互平行（法向夹角<3°）的平面对，d 差即间距；大平面（内点最多）优先判为地板/顶棚。

### §B 船舶/机械精度检测单（mechanical）
```
分段几何精度检测单
对象：____  点云：____（N 点）
【基面】平面 __ 个：方程 + 平整度（robust_sigma）
【孔/轴】圆柱 __ 个：轴线方向、半径 r=__mm（锥形检出时换算等效半径并注明）
【偏差表】逐形状：拟合值 vs 名义值（用户提供或写"—"）、偏差、判据（±__mm）、合格/超差
【建议】超差项的返修提示；无名义值时输出"待比对"字段
【证据】同 §A
```

### §C 文物构件参数卡（mechanical）
```
文物构件数字化参数卡
构件：____（类别：柱/梁/墙/基座…）  点云：____（N 点）
【几何】主要基元参数（柱：轴点/倾角/直径；梁：轴向/截面宽高估计；墙体：倾角与鼓凸 RMSE）
【病害线索】倾角>1° 或 robust_sigma 异常大的面/柱标注"建议病害排查"
【档案】本卡参数可直接录入数字化档案（字段名对齐 §C 括号内术语）
【证据】同 §A
```
