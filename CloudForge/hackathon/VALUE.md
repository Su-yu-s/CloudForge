# 云铸 · 问题价值创新方案（问题价值 = 评分 20%）

> 调研结论先行：云铸的"问题价值"不用编——**江苏省政府的政策文件里已经写着我们做的事**。
> 《江苏省智能建造发展实施方案》明确要求「开展**三维数字化竣工验收备案**」「制定 BIM 交付标准」，
> 南京、苏州均为住建部首批 24 个智能建造试点城市。云铸产出的结构化参数报告，
> 正是"三维数字化竣工备案"需要的内容。

## 一、问题价值的三层叙事（由政策到案例）

### 第一层：政策锚点（评审在地性，江苏省比赛最吃这个）

| 政策 | 与云铸的对应 |
|---|---|
| 《江苏省智能建造发展实施方案（试行）》（省住建厅 2023.1）："开展**三维数字化竣工验收备案**" | 云铸输出 = 可归档的结构化几何参数报告（平面方程/净高/墙厚 + 误差指标） |
| 同方案："制定 **BIM 交付标准**" | 云铸的 JSON schema（schema_version/v1 系数语义）就是一个可交付的参数格式 |
| 南京市实施意见（2023.5）："BIM 智能审查…**竣工验收管理制度**" | 云铸演示主线就是"扫描 → 参数 → 核验" |
| 住建部 24 个智能建造试点：南京、苏州在列 | 作品落地语境 = 试点城市正在推进的验收数字化 |

技术文档加一节「与江苏省智能建造政策的对应」，路演提一句——评审是省学会，在地性直接拉满。

### 第二层：行业断层的真实痛点（有证据链）

点云采集快、**后处理慢**——这是行业公认的断层：

- 三维激光扫描单站采集已降到 **2 分钟**、点距 1mm 以内；
- 但点云到手后：人工逐点判读、拟合、比对设计值——"数据采集耗时长、处理环节繁杂、
  **精度易受人为因素影响**"；传统人工采集"存在主观误差…**难以形成有效标准值**"；
- 船舶行业实证（现代重工 3D 造船系统）：单结构测量从 **10 小时级**缩短——说明
  "扫描数据 → 可用参数"这一步的行业代价是小时/天级。

**云铸的定位一句话**：采集快、出报告慢的断层上，用智能体把"点云 → 参数"压到分钟级，
且每一步可复核（RMSE/噪声σ/软评分随报告交付）——不是黑盒自动化，是**可审计的自动化**。

### 第三层：江苏省本地案例（数字自带冲击力）

- **苏州古城**：姑苏区对 8 处文保建筑采集精密点云 **278.3 亿个**——278 亿个点没人看得完，
  修复师傅需要的是"这根柱的直径、这面墙的倾角"，不是数字海洋。云铸 = 从点云到参数的翻译器；
- **南京城墙**：现存长度 22728.98 米、最高点 67.07 米——这些数字本身就是"点云 → 参数"的产物；
  全维度数字档案的下一块拼图正是参数级结构化提取；
- **船舶**（江苏第一大产业）：分段合拢面识别、外板成形检测（点云 vs CAD 求偏差）、
  合拢管法兰批量测量——学术界用 PointNet++ 做的事，云铸的工具链可直接服务。

## 二、落地创新：一个引擎，三种行业报告（场景 Profile 化）

把 Skill 升级为三场景模式，智能体按场景选预设并输出**行业语义的报告模板**：
同一 C++ 核心，问题价值×3。

| 场景 profile | 预设 | 报告语义 |
|---|---|---|
| **竣工核验**（主推，政策直接命中） | outdoor_planes | 净高/开间/墙厚/平整度（映射 RMSE）→ 可归档"三维竣工备案附件" |
| **船舶分段**（江苏产业） | mechanical_full | 基面/骨材参数 + 偏差表（对照设计值）→ 分段精度检测单 |
| **文物构件**（江苏故事） | mechanical_full | 构件参数卡（柱径/梁截面/墙体倾角）→ 数字档案条目 |

实现成本低：Skill 里加场景分支 + 报告模板三选一；CLI/插件零改动。
